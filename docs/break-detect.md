# Детект «домен ломается самим обходом» — логика и правки

Ветки: `feat/break-detect` (PR) и `zator`. Коммиты: `87711d6`, `de71b3a`,
`727c378`, `b8d5793`.

## Проблема

zapret2 применяет дезинк к TCP-трафику по профилям. Если конкретному домену
обход вредит (сервер не терпит фейки/дизордер, или стратегия злит ТСПУ) —
сайт просто «уходит в отказ», и ни пользователь, ни авторотация не могут
отличить «DPI блокирует» от «обход сам ломает». Ручные профили вообще не
видели отказов: payload-фильтр не пропускал входящие RST до lua.

## Решение — три слоя

### Слой 1: сбор отказов в nfqws2 — `lua/break-detector.lua`

Подключается `--lua-init` и зовётся из обоих оркестраторов:

- `circular_locked` (ручной режим) — сам считает сигналы через
  `z2r_break_track(desync, gate_host, hrec.nstrategy)`; вызов стоит ПОСЛЕ
  лок-ветвления: выключенный локом 0 профиль отказов не генерит;
- `circular_quality` (авторотация) — `z2r_break_note(..., is_failure,
  is_success)` переиспользует уже вычисленные вердикты детекторов.

Сигналы отказа: входящий RST на раннем rseq (≤4096, т.е. разрыв сразу
после ClientHello) и ретрансмиты ClientHello (порог 3). Успех: вошедших
байт ≥32КБ — счётчик отказов сбрасывается.

Состояние пер-хостовое, в памяти процесса: 3 отказа за 120 сек
(`break_fails=`/`break_window=`) → запрос на проверку. Запрос — файл
`/tmp/z2r-break-check/request.<id>` (TSV: id/hostkey/hostname/proto/
strategy), атомарный rename, очередь принадлежит nobody (nfqws2 пишет).

### Слой 2: дифференциальная проба — `lua/break-validator.sh` + иниты

Демон (Entware `S94z2r-break-validator`, OpenWrt procd, systemd-юнит)
забирает запрос и делает две пробы curl:

```
ФАЗА A «без обхода»:  hostname временно в z2r_broken_hosts.txt
                      (горячий exclude_hostlist, TTL 2с) → curl
ФАЗА B «со стратегией»: убран из списка → curl под текущей стратегией
```

Вердикты:

| Вердикт | A (без обхода) | B (обход) | Действие |
|---|---|---|---|
| `BROKEN` | ok | fail | хост ОСТАЁТСЯ в exclude навсегда + строка в `broken_hosts.tsv` |
| `FIXED_BY_STRATEGY` | fail | ok | ничего (обычная DPI-блокировка, обход нужен) |
| `BLOCKED_NOFIX` | fail | fail | ничего (DPI сильнее стратегий) |
| `OK_TRANSIENT` | ok | ok | ничего (ложная тревога) |
| `DEAD` | dns | dns | ничего (домен мёртв) |
| `EXCLUDED` | — | — | уже в исключении, пробы не делаются |

Проба: любой HTTP-код = «сервер ответил» (4xx/5xx тоже — транспорт пробит),
один повтор на срез (DPI режет выборочно). Результат — `result.<id>`,
lua забирает его на следующих пакетах хоста.

### Слой 3: горячее исключение — config.default

`exclude_hostlist=/opt/zator/lists/z2r_broken_hosts.txt` добавлен в 10
TCP-строк оркестраторов (ручные 1/2/3/3S/4/9 + авто 3/4/9; UDP не тронуты;
fallback-блок 8 НЕ тронут — sed'ы переключателя RST-guard матчат точную
строку payload внутри `#Z2R_FALLBACK`). `circular_locked` при совпадении
отдаёт ранний `VERDICT_PASS` ПОСЛЕ `orchestrate()` — план отменен, домен
идёт чистым. Файл перечитывается с TTL 2с: добавление/удаление домена
работает без рестарта.

## RAM-кэш вердиктов (перезапускостойкость)

Проблема: кулдаун после вердикта жил только в памяти nfqws2 и терялся при
рестарте — домены гоняли повторные диффпробы. Решение (коммит `b8d5793`):

- демон пишет каждый вердикт в `/tmp/z2r-break-verdicts.tsv`
  (tmpfs: `hostkey<TAB>вердикт<TAB>unixtime`, атомарный upsert);
- lua перед постановкой в очередь сверяется с кэшем (перечитывает раз в
  30с): свежий вердикт задаёт кулдаун без пробы — BROKEN 6ч, остальные
  15 мин; работает и сразу после рестарта nfqws2;
- чистка: записи старше 24ч (`Z2R_BREAK_VERDICT_TTL`) удаляются на старте
  демона и раз в час — домен позже перепроверится заново.

Итог: «рабочие сайты остаются рабочими в любом режиме» — подтверждённый
BROKEN живёт в постоянном exclude-файле, кэш в RAM переиспользуется и
не растёт.

## Обязательные сопутствующие правки

1. **`payload=...,empty` у ручных TCP-профилей** (`de71b3a`): без `empty`
   входящие RST вообще не доходили до lua — детектор был слеп к разрывам
   в ручном режиме. Чтобы каждый ACK не делал полную работу оркестратора,
   в `circular_locked` добавлен ранний гейт пустых пакетов без RST
   (зеркало авторского `circular_quality`).
2. **source-строка `dpidetect.sh` + самолечение lib-файлов** (`727c378`):
   `Z2R_LIB_FILES` — только чек-лист, реально библиотеки подключаются
   поштучными `source`-строками; недостающие файлы докачиваются
   best-effort при старте (лаунчер при недоступном GitHub API кладёт
   только запасной список).

## Ручной вход: `lib/dpidetect.sh`

П.12 подменю стратегий и п.9 управления доменами: та же дифференциальная
проба по движку `z2r_tls_*` (TLS 1.2+1.3 параллельно, докачка 64КБ,
опционально tcpdump-подтверждение RST через `DPIDETECT_TCPDUMP=1`), плюс
меню авто-исключённых доменов с возвратом в обход. Прежний лок
восстанавливается при любом исходе, включая Ctrl+C.

## Наблюдение на роутере

```
ps w | grep break-validator                     # демон
ls /tmp/z2r-break-check/                        # очередь (.work = в работе) и результаты
cat /tmp/z2r-break-verdicts.tsv                 # RAM-кэш вердиктов
cat /opt/zator/lists/z2r_broken_hosts.txt       # постоянные исключения
cat /opt/zator/extra_strats/cache/orchestra/broken_hosts.tsv   # журнал BROKEN
```

## Тесты

`tests/break_detect_smoke.sh` — статическая разводка (хуки, exclude на 10
профилях, деплой, иниты от nobody) + логика демона на моке curl: все 6
вердиктов, BROKEN оставляет исключение, EXCLUDED не пробует, битый TSV
молча удаляется; кэш вердиктов пишется и чистится. `tests/dpidetect_smoke.sh`
— классификатор, интеграционные вердикты, восстановление локов, tcpdump.
Живая проверка на OpenWRT-стенде с реальным ТСПУ — meduza.io (3 RST →
запрос → FIXED_BY_STRATEGY), kimberlite.io (BROKEN → исключение).
