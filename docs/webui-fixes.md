# Правки Web UI — кейсы, причины, фиксы

Ветки: `fix/webui-start-hardening` (PR автору) и `zator`.

## 1. Установка панели не должна валиться без nohup

Кейс (OpenWrt, фиды opkg недоступны): `opkg install coreutils-nohup`
падал из-за недоступности downloads.openwrt.org → гейт
`webui_ensure_runtime_deps` ронял всю установку панели со словами
«Не удалось найти или установить nohup», хотя `run-webui.sh` умеет
стартовать и без него.

Фикс: отсутствие nohup — предупреждение, не ошибка. В раннере цепочка
запуска расширена: `nohup` → busybox-applet nohup → **`setsid`** →
`( trap '' INT QUIT HUP; exec ... ) &` — фоновый запуск с редиректом
(тот же приём, что `z2r_service_action` для инит-скриптов).

## 2. Диагностика на OpenWrt: syslog, а не несуществующий лог

Кейс: статус «запуск не удался — см. лог /opt/zator/webui/run/webui.log»,
а файла нет. Причина: на OpenWrt панель стартует через procd, который
вывод демона отправляет в syslog — webui.log в этом режиме не создаётся
вообще (его пишет только самозапуск через nohup на Entware).

Фикс: п.4 «Диагностика Web UI» на WRT дополнительно печатает
`logread | grep -iE "uhttpd|webui|run-webui"` (последние 15 строк);
сообщение о неудачном старте на WRT указывает на logread.

## 3. На Keenetic родной uhttpd_kn приоритетнее Entware-uhttpd

Кейс (телеграм, Andrey Rodin): панель не стартовала, диагностика
показывала `webui_server_type: uhttpd` при УСТАНОВЛЕННОМ пакете
`uhttpd_kn`; «Оно почему-то ломилось в uhttpd вместо uhttpd_kn» (Никита);
лечилось только выносом компонента DDNS.

Причина: `webui_server_type` и `available_servers` проверяли `uhttpd`
первым — на боксе с обоими серверами выбирался Entware-uhttpd,
конфликтующий с компонентами прошивки. Вдобавок его диагностика писала
«uhttpd_kn: нет» при установленном пакете — бинарей лежал вне PATH.

Фикс: `uhttpd_kn` проверяется первым (и в детекте, и в раннере); поиск
дополнительно прямым файлом `/opt/sbin/uhttpd_kn`; диагностика помечает
такой бинарей как «вне PATH». На OpenWrt/VPS поведение не меняется
(uhttpd_kn там не существует).

## 4. Старт после стопа: гонка с умирающим uhttpd

Кейс (телеграм, Keenetic): при переустановке zapret2 панель
останавливалась → файлы обновлялись → стартовала — и не поднималась
(`stopped:uhttpd`), поднималась только со второго запуска z2r. Похоже на
гонку: старт ловит ещё не умерший uhttpd, держащий порт 17682.

Фикс двойной:

- `webui_stop_service`: после стопа ждём исчезновения слушателя порта
  (до 4с, netstat);
- `webui_start_service`: при неудаче — пауза 2с и вторая попытка, прежде
  чем рапортовать о неудаче.

## Тесты

`tests/webui_smoke.sh` прогоняется на всех четырёх фиксах (19 ассертов);
ассерт сообщения о мёртвом старте ослаблен до корня «Диагностик» — в
сообщении родительный падеж, а разные grep-реализации с кириллицей
давали нестабильный результат.
